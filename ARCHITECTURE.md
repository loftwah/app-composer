# Architecture

For module ownership inside the native editor and maintenance of copied public UI assets, see [Maintaining the source](docs/source-maintenance.md).
Reviewed 13 October 2026.

Composer is an Astro/EmDash Cloudflare Worker. EmDash owns catalogue descriptions and documentation in its own D1/R2. The independently deployed Guestbook and Showcase own separate GitHub histories, D1 state and storage. Composer mounts separately pinned integrated Worker services under one origin. Standalone upstream deployments cannot change this consumer code. Each integrated service uses the app-owned D1/R2, so current moderation remains shared while executable versions stay pinned. Promotion validates exact reviewed source pins and explicitly deploys the integrated services. The Showcase asks a versioned generic item provider for current eligibility; it never copies a private image or treats saved approval as permission. Each service remains deployable without Composer or Woodhouse.

External Codex is the execution adapter. Get Ready checks its real workspace through a repo command, not browser guesses. Init and Explorer share a versioned specification. The trusted deployer uses existing scoped runtime credentials; public HTTP cannot trigger builds or deploys. Maintained reference deployment builds a verified temporary snapshot of the exact authored Hello main, checks its independent target contract and existing route, then rechecks original and copied bytes around build/provider waits. It shares the same isolated pinned-Wrangler upload path as the owned starter: service credentials stay out of tests/dry-run, inherited CI/API/Node overrides are stripped, and ignored dotenv/hook files are excluded. This is the Get Ready adapter boundary; the independent repository’s manual deploy command is separate. Only reviewed authored repositories are executable. The local-tool installer also accepts an unchanged personal private copy at the actual maintained source SHA, with fresh GitHub owner/permission and full byte checks; it installs from isolated reviewed dependency inputs. This installation operation never applies Init configuration or runs a cloud deployment. A separate local-only target preparation verifies the existing account and unused workers.dev destination, rechecks actual unchanged owned source and writes only a bounded Wrangler configuration through its original unshared regular-file inode. The preparation remains action-required; the name is not reserved. Initial owned deployment accepts a committed/pushed private personal main whose tracked tree/modes match actual maintained main except for that exact bounded Wrangler profile. The same engine builds/tests a temporary source snapshot, excludes ignored files and unrelated credentials/CI/API overrides, checks name availability again and verifies routing plus exact HTTPS app/source/title/contract. Existing/partial targets are refused; availability is not an atomic reservation. Owned Init prepares only the validated three-field config through the same engine after old-source HTTPS verification and full source/inode checks. The explicit owned update accepts those fields, requires previous repository source/history and actual active single 100% Worker version, rechecks that version after final HTTPS IO and shares the isolated build/upload path. Provider reads are snapshots, not CAS. General source updates and cleanup remain unsupported. Unknown registries are inspected as JSON, never installed or executed automatically. Local build does not claim to sandbox arbitrary downloaded source.

Owner API tokens live in runtime secrets. Browser writes require explicit owner authentication and same-origin requests. EmDash administrative routes stay closed until Access JWT verification is configured; public read queries remain available. Preview resources are separate. Public demos use fictional seeded content and invitation-only submission; no unbounded anonymous media upload. Carry / forward encrypts locally and never sends a master key or plaintext to a server or model.


Wrangler session reuse, reviewed 15 October 2026: the local HTTPS routing probe prefers an explicitly supplied API token; otherwise the pinned workspace Wrangler checks the existing selected OAuth identity's account and resolves its current token through the supported CLI. Only fixed account-owned Worker routing reads receive that transient credential. Workspace subprocess logs/metrics are disabled, output is captured, and failures/results never include credentials. There is no credential fallback on denial, automatic login, profile selection, new provider scope or receipt authority. Wrangler may refresh its own existing OAuth cache. Explicit token-only setup/deploy and workspace-free domain diagnosis stay separate.


Generated published entry routes, reviewed 15 October 2026: the content-project recipe includes fixed `/entries/[id]/index.astro` source and shared layout/field rendering. Stable native content IDs avoid a schema/slug migration. Native collection queries explicitly select published status and the exact bounded ID; route/query strings never select a collection or status. Missing/private public results omit content and return404; errors return503. Detail responses are no-store and local indexing remains disabled. Existing native authenticated preview context retains EmDash's authority; this slice proves ordinary public requests only. The recipe never updates existing projects or provisions a customer destination.


Existing-session starter operations, reviewed 15 October 2026: the same private selected-credential resolver now serves explicit target preparation and bounded maintained/owned deployment/version reads. A deployment freezes one credential after source review; all Cloudflare reads and its sole upload retain it. No denial/expiry fallback or upload retry is added. Source/GitHub probes keep the original host environment; tests/dry-run and upload use a temporary HOME/config directory without cached user logins, and only upload receives the token. Native scope/ownership/source/previous-version rechecks and exact HTTPS acceptance remain. No new operation, permission, hosted service or MCP cloud-write tool. Workspace-free domain diagnosis remains token-only; real OAuth customer consent/refresh/upload acceptance is separate.


Reviewed 15 October 2026: project inspection v2 separates declared EmDash intent from bounded fixed package metadata on disk. It does not load package code or dependency exports. npm directories and pnpm links contained within the selected real node_modules are observed; external/shared modules or linked package files are refused. Stable read-only package hardlinks are accepted without relaxing guidance/preparation file rules. Legacy v1 project reports retain unknown installation. This is one existing project inspector shared across library/CLI/MCP and the browser boundary, not an additional readiness engine or compatibility certification.


Ownership receipt preservation, reviewed 15 October 2026: the existing personal-starter operation preflights real private storage and strict bounded legacy/current receipts before provider I/O. It reserves an exclusive random recovery descriptor before creation, rechecks selected storage and receipt identity/bytes across provider waits, and publishes complete bytes with an exclusive hard link before removing only its own staging name. Existing destinations, legacy temporary links and observed owner edits are never replaced. A provider success with changed storage retains any surviving recovery copy for agent inspection and stops before push; it adds no automatic retry, adoption or cleanup authority. Explicit resume, actual GitHub identity/source/ref checks and source-only pushes remain required. Native path observations are not a full concurrent filesystem sandbox.


Domain diagnosis with an existing session, reviewed 15 October 2026: the same fixed read-only zone/DNSSEC/NS/DS function accepts an optional host-selected absolute workspace. With no explicit API token it reuses the existing pinned Wrangler/account credential resolver once; token presence retains priority, including invalid/denied selections. CLI exposes that explicit workspace and MCP uses its existing host-fixed workspace, never model scope. No new tool, scope, login, provider write, automatic retry or readiness receipt is introduced. Wrangler may maintain its own login cache. Standalone workspace-free callers remain token-only; report v1 and public resolver credential isolation are unchanged.
