# Architecture
Reviewed 13 October 2026.

Composer is an Astro/EmDash Cloudflare Worker. EmDash owns catalogue descriptions and documentation in its own D1/R2. The independently deployed Guestbook and Showcase own separate GitHub histories, D1 state and storage. Composer mounts separately pinned integrated Worker services under one origin. Standalone upstream deployments cannot change this consumer code. Each integrated service uses the app-owned D1/R2, so current moderation remains shared while executable versions stay pinned. Promotion validates exact reviewed source pins and explicitly deploys the integrated services. The Showcase asks a versioned generic item provider for current eligibility; it never copies a private image or treats saved approval as permission. Each service remains deployable without Composer or Woodhouse.

External Codex is the execution adapter. Get Ready checks its real workspace through a repo command, not browser guesses. Init and Explorer share a versioned specification. The trusted deployer uses existing scoped runtime credentials; public HTTP cannot trigger builds or deploys. Maintained reference deployment builds a verified temporary snapshot of the exact authored Hello main, checks its independent target contract and existing route, then rechecks original and copied bytes around build/provider waits. It shares the same isolated pinned-Wrangler upload path as the owned starter: service credentials stay out of tests/dry-run, inherited CI/API/Node overrides are stripped, and ignored dotenv/hook files are excluded. This is the Get Ready adapter boundary; the independent repository’s manual deploy command is separate. Only reviewed authored repositories are executable. The local-tool installer also accepts an unchanged personal private copy at the actual maintained source SHA, with fresh GitHub owner/permission and full byte checks; it installs from isolated reviewed dependency inputs. This installation operation never applies Init configuration or runs a cloud deployment. A separate local-only target preparation verifies the existing account and unused workers.dev destination, rechecks actual unchanged owned source and writes only a bounded Wrangler configuration through its original unshared regular-file inode. The preparation remains action-required; the name is not reserved. Initial owned deployment accepts a committed/pushed private personal main whose tracked tree/modes match actual maintained main except for that exact bounded Wrangler profile. The same engine builds/tests a temporary source snapshot, excludes ignored files and unrelated credentials/CI/API overrides, checks name availability again and verifies routing plus exact HTTPS app/source/title/contract. Existing/partial targets are refused; availability is not an atomic reservation. Owned Init prepares only the validated three-field config through the same engine after old-source HTTPS verification and full source/inode checks. The explicit owned update accepts those fields, requires previous repository source/history and actual active single 100% Worker version, rechecks that version after final HTTPS IO and shares the isolated build/upload path. Provider reads are snapshots, not CAS. General source updates and cleanup remain unsupported. Unknown registries are inspected as JSON, never installed or executed automatically. Local build does not claim to sandbox arbitrary downloaded source.

Owner API tokens live in runtime secrets. Browser writes require explicit owner authentication and same-origin requests. EmDash administrative routes stay closed until Access JWT verification is configured; public read queries remain available. Preview resources are separate. Public demos use fictional seeded content and invitation-only submission; no unbounded anonymous media upload. Portable AI State encrypts locally and never sends a master key or plaintext to a server or model.
