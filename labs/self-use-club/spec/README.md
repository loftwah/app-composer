# Exported Composer specification

Captured on 25 October 2026 from the real public App Composer instance at source
`86514680720702ce30157671652981e388b77f65`. No local hand-authored view of a
Composer format replaces these files; each one was downloaded or generated by the
live form and then saved here.

## Journey used

1. **`/setup`** — selected **New project**, entered the project reference and the
   club outcome, left "Let the agent inspect and adapt", did not request
   publishing, and used **Download Markdown**. Output: `project-setup.md`.
2. **`/prompts#build`** — used the **Build an app** job with project, goal,
   audience and details, then **Download Markdown**. Output: `requests/build.md`.
3. **`/init/content`** — for events, notices and enquiries:
   - wrote a plain-language content brief;
   - used **Copy field-design request** (the run forced the documented clipboard
     fallback so the generated request stayed visible and could be saved);
   - an agent returned a version-1 model JSON for that brief;
   - imported it into the real editor;
   - downloaded the validated model and EmDash seed, and saved the implementation
     handoff.
   Outputs: `models/*.model.json`, `models/*.downloaded.seed.json`,
   `handoffs/*.md`, `requests/*.design-request.md`.
4. **`/prompts#change`** — after the first acceptance run, used the **Change an
   existing app** job for the volunteer-capacity request. Output:
   `requests/volunteers.md`.

`export-record.json` holds the machine-readable record of the first exports.
`manifest.json` holds the source commit, route steps, file bytes and SHA-256.

## What Composer emitted versus what the agent wrote

Composer emitted the project guide, the build/change requests, the design
requests, the validated model and seed exports, and the implementation handoffs.
The three model JSON bodies were written by an agent **from Composer's own design
request**, then imported, validated and re-exported by the real editor. The
portable editor is designed for that loop, but the form did not invent the field
structure by itself. The club and volunteer code was not generated by
Composer; it was implemented by the agent from this bundle.

The exact exported files are deliberately preserved rather than rewritten after
the code was implemented.

## Filename note and fixed follow-up

The first export produced three different models whose downloads were all named
`app-composer-content-model.json` (and three seeds named
`emdash-content-seed.json`). The browser renamed the collisions. The files here
were renamed by hand for clarity. A focused Composer change now derives the names
from the collection:

- `events.app-composer-content-model.json`
- `events.emdash-content-seed.json`

See `tests/content-model-downloads.test.mjs`. This worktree change is not deployed.

## Verify

```sh
node -e "const m=require('./manifest.json'); const {createHash}=require('node:crypto'); const fs=require('node:fs'); for (const f of m.files) { const b=fs.readFileSync(f.path); if (b.length!==f.bytes || createHash('sha256').update(b).digest('hex')!==f.sha256) throw Error(f.path); } console.log('all', m.files.length, 'files match');"
```

The model files validate with Composer's own implementation (run from this directory):

```sh
node --input-type=module -e "import {readFileSync} from 'node:fs'; import {validateContentModel,emdashSeed} from '../../../lib/content-model/index.mjs'; for (const id of ['events','notices','enquiries']) { const model=JSON.parse(readFileSync('models/'+id+'.model.json')); validateContentModel(model); emdashSeed(model); } console.log('three models valid');"
```

See `labs/self-use-club/README.md` for the complete local run.

## Boundaries

The setup guide is a portable instruction, not a readiness receipt. The model
editor never creates a collection or publishes content. The form exports contain
no credentials, and no account, deployment or permission was created. The
fictional club was chosen by the agent under the run's brief, not by Composer.
