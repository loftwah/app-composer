unrelated service. They preserved it and used an unused localhost port with the
same existing handler. The default Python was below the documented minimum;
they found installed Python 3.14.7 instead. A slow local reverse-DNS lookup
required bounded startup observation. One session also recovered from shell
inspection/bootstrap errors, a rejected initial cleanup command and an
insufficient five-second startup observation. No person supplied rescue,
credentials or new permissions. Those autonomous recoveries are deliberately
recorded as `completed-after-rescue`, rather than advertised as clean first
attempts. The ledger's rescue count includes these local agent recoveries and
is separate from `humanActions`, which is empty.

The actual application was opened, not inferred from a healthy process. The
404 route and browser Back recovery were exercised. Original owner title,
welcome, note and source bytes remained intact. The guide's sentence about
preserving an existing database did not invent one: the fixture has none.
Every owned service, browser tab and temporary root was removed; the unrelated
listener was left running. Bounded raw evidence is retained in the operator's
ignored `output/backlog/setup-eval-existing-{1,2,3}` folders, not published with
local paths, process IDs or browser session data.

This establishes three observed local existing-project attempts, with disclosed
recovery. It does not complete #292: new-project attempts, separate-session
