## Release rules for this session

- One integration writer (this session). Worker branches merge into `main` only
  after their focused checks pass; production uses the existing
  `pnpm deploy` clean-pushed-main guard, once per coherent candidate.
- Serialise deployments: Studio release then Composer release (or the reverse)
  never overlap. No new release gate, service, secret or scheduled job.
- Each closure gets one concise receipt in the owning issue and a GitHub
  read-back. Duplicate/obsolete closures cite the canonical owner.
