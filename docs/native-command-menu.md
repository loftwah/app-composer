# Native Apps menu

The native integration is an ordinary extension of the accepted Apps menu, not another palette implementation. `src/integrations/native-menu.ts` uses Astro's supported page-script injection and dynamically imports the browser adapter only for `/_emdash/admin` paths. EmDash1.2 owns its header and router; its documented React extension surfaces have no global header slot. No vendor file, React host, navigation history or header selector is patched.

The adapter mounts one app-owned control and dialog outside `#admin-root`, so React route changes retain that one instance. The native host's `data-mode` controls its theme. A small fixed Apps control respects safe areas and hides while a software keyboard occupies the viewport; native editor controls remain independent. Classic consumers still load `public/brand/launcher.js` as a normal script. Its idempotent `AppComposerLauncher.mount()` / `unmount()` API and controller `dispose()` restore body styles, abort listeners and restore initial markup. Native unload disposes its control/assets; cached pages close the modal without duplicating the instance.

Only native Cmd/Ctrl+K uses window capture to select this menu before the host's unrelated palette. Ordinary keys retain propagation/default behavior. Composing Cmd/Ctrl+K blocks only other shortcut handlers, preserving the input method's default action. Public shortcut behavior remains unchanged. Disposing the controller restores the host's existing shortcut behavior.

The native adapter reads one bounded same-origin manifest to select declared Workspace access, Outcomes, Maintenance and Enquiries shortcuts. Failure leaves the base menu and ordinary Apps link available. Availability is navigation metadata, never authentication or workspace authority. Every native API retains its original permissions. Only a single validated workspace selector is preserved on same-origin Creator studio links; invitation, app and other query values never travel to public/external app links. Current-page marking refreshes when the menu opens.

Maintained source: `src/browser/launcher.ts`, `public/brand/launcher.css`, `src/browser/native-launcher.ts` and `src/styles/native-launcher.css`. The classic output is checked by `scripts/launcher-assets.mjs`. A separate DOM-only/no-Node compiler checks the native adapter; this avoids importing native-only code into standalone generated sites. Those sites retain their owned classic source/compiler/assets through the existing finite project-copy contract.

Each of the five independent mini-app repositories must receive the two maintained launcher distributions through the existing explicit asset-copy workflow, and pass its own checks/release boundary. Source changes here do not update those apps. Exact app heads, source hashes, browser scope, drift and release status belong in the ignored run receipt and #11; no family-wide or production claim follows from this source candidate alone.

References checked against installed EmDash1.2/Astro7.3.5: [EmDash React admin extensions](https://docs.emdashcms.com/plugins/creating-native-plugins/react-admin/), [Astro integration API](https://docs.astro.build/en/reference/integrations-reference/#injectscript-option). Local package/runtime behavior remains the qualification authority when documentation differs.
