- Publish approved brand/work/profile links after checking their current destination and meaning. Public repository visibility is not blanket personal disclosure approval.
- Keep the CV and explicitly withheld personal material out of public data, DOM, console output, exports and images. Do not retain their URLs in the public catalogue.
- Legacy Linkarooie `hidden` can mean a browser-console discovery feature. It is a presentation marker to inspect, not a universal privacy classification. Current app `draft`, `hidden`, `rejected`, `deleted` and revoked-provider states remain actual enforced visibility rules. Never unhide those records as a branding/import side effect.
- Downscope is excluded from public featuring for now, by MP's direct choice. Unrelated/reassigned old destinations remain quarantined. Do not publish personal listening accounts, family details or unnecessary old social-preview biography.
- Third-party releases are credited links, not Loftwah-owned artist accounts or rehosted recordings. Verify the precise production/mixing/engineering/performance role before presenting it.
- A reachable page is not proof of a complete product, current ownership, credentials, a playable release or a music credit. Blocked/captcha-only responses remain unverified rather than dead. Retain current HTTP/DNS check dates.

## Owner and guest access

MP clarified that the shared guest puzzle code and owner login must be separate. Keep existing private owner credentials; their server credentials already work for both independent and mounted Guestbook/Showcase exports. No credential values belong in this brief, source catalogue, console or public spec. The local private access note explains entry points and credential locations.

The requested `hunter2` guest experience is submission-only: create a new pending contribution, never publish, moderate, edit/delete existing entries, read unpublished records/media, export owner data or change settings. The code is a playful shared affordance, not the security boundary. Server-enforced capabilities, consent, byte/text/queue/daily limits, sanitisation, rate limits and moderation must carry the boundary. Keep the generic feature default-off and make owner activation explicit. Guest text-first participation is the preferred product direction; invited photos retain their current protections until their separate guest path qualifies. No guest route may authenticate as the owner.

Guest postcards are implemented as an optional, default-closed capability. The public puzzle creates new pending items only; it never creates an owner session. Opening a deployment requires negative API tests, owner/guest journeys, direct and composed visibility checks, exact source pins, preserved owner records and guarded release evidence. Actual activation and source/version evidence belong in #11; this brief alone never proves a deployment is open.
