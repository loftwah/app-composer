## Copied-source boundary

Only disposable copies change. The reused lifecycle selects supported EmDash native authentication instead of the production Access wrapper and removes email delivery. The extra platform qualification seam changes the copied `src/plugins/stacks.ts` factory to supply `PLATFORM_PUBLIC_FETCH` through a fixed `PLATFORM_PUBLIC_PAGES` self service binding. Requests reach the actual local `/s` and mounted app handlers without owner headers. Browser/imported inputs cannot select the endpoint or any credential. This establishes local route verification separately from the production public edge.

Receipts include the original and derived lifecycle hashes, exact copied factory patch, copied authentication configuration and entry hashes, temporary source tree identity, independent app pins, native user roles and bounded operation results. Source and fixture drift is rejected before native writes. Tokens, private browser state, passkey material, database files, certificates and copied source remain inside one owned temporary root. The `finally` handler closes the owned browser, invokes the reused identity-checked lifecycle stop, and removes that root. A failed stop preserves its process handle and reports cleanup failure rather than erasing the only recovery marker.

Each fictional actor's owned browser context records one continuous 1440 × 1000 WebM, beginning before native authentication and ending at normal context closure. The optional `output` argument to `authenticateNativeActors` enables recording; the lifecycle supplies an owned temporary location and registers each context immediately. No developer tools, network payloads, raw cookies, storage-state export or passkey key material are recorded. Authentication calls run in page evaluation, so invitation tokens are not navigated to or rendered. Actual rendered footage still needs inspection before sharing.

The complete browser recording window is capped at six minutes; exceeding it closes the owned browser and fails qualification. Each retained actor file is capped at 32 MiB. Normal context closure flushes the raw footage before browser shutdown. Existing `ffprobe` supplies actual duration, codec, frame size and rate. Only bounded useful files are copied into ignored `output/platform-native/`, with actor, source identities, SHA-256, bytes, duration and explicit local-admission scope in the receipt. Files are neither edited nor sped up. A missing, oversized or uninspectable recording fails the capture result without retaining its temporary project. These raw recordings are evidence inputs, not completed #221 films.

## Qualification sequence

1. Native setup and passkey sign-in establish the operator. Actual role invitations register the creators and the ordinary app user; logout/sign-in and `/auth/me` confirm persisted roles.
2. The actual workspace UI creates two teams and accepts editor invitations. The policy UI enables bounded standing policy. Creator attempts to configure that policy are refused.
3. Each creator requests an app through the actual platform UI. The actual app-owned resources and published StackView pages must complete with distinct retained identities.
4. Cross-team platform reads/writes and member dispatch are refused. Ordinary role10 platform reads/writes must return HTTP403. A cross-team media selector is denied before item access; an empty collection cannot establish protection of an existing private image.
5. An explicit native member grant dispatches a moderation list through the actual named service. A separately granted contribution is refused because this recipe closes public guest contributions. No policy, token or database bypass opens it.
6. Team A updates its title through the native UI, retaining request, stack and resource identity. Team B must remain unchanged. A sensitive-data request is refused before app allocation.
7. A fresh context without a native session reads the actual local public StackView and mounted app pages for both teams and checks their exact current names.
