Issue: [#411](https://github.com/loftwah/app-composer/issues/411). Method: the pinned
[`untangle-codebase`](../.opencode/skills/untangle-codebase/PROVENANCE.md) skill
(`f3cf477`), core pass only. The optional Comments and Tests add-ons were not adopted;

The goal was not a rewrite. Each change removes a place where two pieces had to change
together without the code saying so. Behaviour and the existing authority boundaries are
unchanged.

## Reviewed and retained

- `src/lib/*.mts` with generated `.mjs`/`.d.mts` copies is the maintained-source workflow,
  not duplication. Edit the `.mts` source and run the relevant `--write` command.
- The curated format allowlist, migration-order guard, composition pins and provider
  inventory checks already fail loudly on drift. Do not add a second registry.
- `catch {}` sites sampled in the audit are bounded with stated intent (browser storage,
  stream cancellation, keepalive). None hides a product success.
- `tests/temporary-storage.test.mjs` and `tests/readiness-owned-tools.test.mjs` skip on
  unsupported hosts by design; they are not disabled tests.
- The `lib/get-ready/index.mjs` barrel and subpath exports are the published consumer
  boundary.

## Not changed here

- The report and stack share-image pipelines duplicate Resvg setup. Merging them is a
  sensible follow-up, but it changes rendered pixels and belongs with its own visual and
  release evidence.
- The Get Ready package scripts repeat archive names and file lists. The packaging tests
  already fail on drift; deriving the names is useful but not urgent.
- Overview/App resources now read independent records concurrently. The resource inventory
  waterfall has measured evidence in `output/` during the run; the full before/after
  record belongs to #407.
