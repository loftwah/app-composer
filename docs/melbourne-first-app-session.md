# Melbourne first-app session

**Opening question**

> What is one thing you have wanted online but never got around to making?

Give the participant time to describe who would use it and what they’d try first. Agree on one result they can show someone. Identify an existing tool or integration that could do the job before committing to a build.

## Before the session

- Ask the participant to bring a laptop, their existing coding-agent sign-in, and GitHub and Cloudflare accounts they control if they already have them. A custom domain is optional. Keep a supported browser available and let the agent check its actual tool access.
- Open [Discover](https://composer.loftwah.com/discover), [Get Ready](https://composer.loftwah.com/ready), [the free-first guide](https://composer.loftwah.com/ready/start-for-free) and [the rehearsal](https://composer.loftwah.com/articles/cloudflare-app-rehearsal).
- Agree separately on recording and publication. Let the participant review identifying footage and approve release. Pause screen capture for account selection, credential entry, MFA, billing details and permissions.
- Use fictional content during the demonstration. Keep publication, purchases and account changes in the participant’s hands.

## Work through one useful result

1. Write down who it serves, what they can do, and one success check. Choose reuse, integration, purchase or a small build. For the fallback, use a club that needs an easy way to fill a workshop form and start with [Paperwork in Init](https://composer.loftwah.com/init/paperwork).
2. Choose the participant’s existing agent in Get Ready. Copy the maintained setup prompt. Have the agent inspect its machine, tools and permissions before asking the participant to act.
3. Let the agent prepare the app and test the core job. Use a participant-controlled GitHub repository and a new approved `workers.dev` target when the supported path fits. The participant completes normal provider sign-in, confirms the account and approves publication.
4. Open the live URL signed out and try the core action. Ask the participant for one improvement. Release it to the same target and check the new revision. For Club Forms, add the instruction to save and bring the completed form.
5. Show the participant the repository, Cloudflare account, public address and estimate of recurring costs. Ask them to explain in their own words what they can change and where they would look for a bill. Have them retain the source and setup instructions.

## Add this to the maintained setup prompt

> The person using this app is [audience]. They need to [one useful task]. First check whether a working example or existing tool already solves it. Use my existing agent and accounts and tell me the proposed recurring cost before any commitment. Start with a small feature and fictional test data. Show me the result locally, then ask me to confirm the GitHub repository, Cloudflare account and unused target before publishing. Verify the public URL in a separate browser, help me make one meaningful change, and show me how to check the updated version and keep operating it.

## Film the moments that establish the result

- **The idea.** Record the opening question and the participant describing the job in their own words.
- **The choice.** Show the relevant existing app or recipe and why it fits. Capture the agent choice and the copy action.
- **The proof.** Show the first useful interaction and a signed-out tab opening the verified public URL. Resume recording after the participant has completed any private steps.
- **The change.** Capture the participant asking for the improvement, the new behaviour and the ownership handoff. End with what the participant would do next, in their own words.

## Keep the evidence

- Record the start time, first useful interaction, exact live revision and deployment time for the first release and the follow-up. Keep the public URL and a safe screenshot at desktop and phone widths.
- Record human actions, stalled steps, the recovery result and any manual handoff. Mark each cost as estimated, observed or unavailable. For AI, record model, calls, attributable usage and the provider’s billing coverage.
- Label the session as an operator rehearsal or an independent participant trial. Retain the approved quote or an accurate summary of the participant’s feedback. Keep the original or unapproved footage private.
- Put the receipt on [#425](https://github.com/loftwah/app-composer/issues/425) and the measured trial on [#1332](https://github.com/loftwah/app-composer/issues/1332). Use the existing Share example for public-safe material.
