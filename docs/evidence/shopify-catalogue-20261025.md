# Shopify product-launch companion — 25 October 2026

Issue #293 / #105. This bounded outcome helps a creator prepare product links and identify missing publication/artwork/image descriptions for a Composer campaign. Shopify retains storefront, checkout, orders and fulfilment ownership. It reads no customer or order records and performs no financial, fulfilment or publication action.

The existing native Orders page now includes the product-launch review, separate from its explicitly fictional financial lab. An expandable two-product fictional example works without a merchant. Product links are shown only for active products with an observed Online Store URL on the selected shop or its observed primary domain. Draft/archived content stays inside private native administration; no public export or sharing action is introduced. Twenty most recently updated products are the maximum; truncation is explicit. A previous successful client observation is visibly dated when a later authorised provider check fails; losing the private response clears retained metadata.

The server adapter is default-off. It requires `SHOPIFY_READ_ENABLED=true`, a merchant-authorised `SHOPIFY_ADMIN_ACCESS_TOKEN` with `read_products`, canonical `SHOPIFY_SHOP_DOMAIN`, `SHOPIFY_WORKSPACE_ID` and `SHOPIFY_RESOURCE_ENVIRONMENT` exactly matching the selected Composer workspace/environment. These are operator references, never Init/export fields. No bindings, credentials or merchant account were provisioned in this run. A signed-in creator with owner/editor access is required. Membership is checked again immediately before the provider read and after it before returning private drafts.

The connection-status GET makes no provider call. Explicit Check store catalogue uses one fixed Admin GraphQL product query at API **2026-10**, ten-second timeout, 128 KiB response ceiling, no redirects and no retries. It validates returned shop identity and `X-Shopify-API-Version`; API fallback is refused. Wrong shop, scope/token refusal, throttling, partial GraphQL results, unsafe links and unavailable/malformed replies produce redacted states without exposing response errors or secrets. Shopify sends the product metadata; Composer does not infer stock, sales, checkout readiness, payment, unique customers or fulfilment from it.

Official [products query](https://shopify.dev/docs/api/admin-graphql/2026-10/queries/products) and [Shop fields](https://shopify.dev/docs/api/admin-graphql/2026-10/objects/Shop) were checked on 25 October; Shopify's documentation redirects these to its current 2026-10 latest view. This does not prove a merchant connection.

Checks: `node --test tests/shopify-catalogue.test.mjs tests/orders.test.mjs tests/plugin-release-comparison.test.mjs`; frozen existing dependencies; `pnpm check:types` zero errors / zero warnings. Native route registration adds only `shopifyCatalogueRead` and `shopifyCatalogueCheck` in the existing creator plugin. No database migration, persistent catalogue copy, secret change, production checkout, payment, real order, subscription or independent app source-pin change occurred.

Real provider acceptance remains gated on an owner-selected development store/custom app, approved `read_products` access and scoped token installation. Native browser pixels and production identity belong to the coordinator's integrated release. Customer/order import, OAuth/app distribution, checkout, webhooks and protected customer data are unimplemented and remain open. A local contract test is not a deployed Shopify integration.
