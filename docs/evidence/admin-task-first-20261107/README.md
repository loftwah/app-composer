# Admin task-first audit — 7 November 2026

Scoped [#313](https://github.com/loftwah/app-composer/issues/313) live audit. The
native Composer admin was exercised in the real Access-protected owner session at
1440 × 1000 and 390 × 844. Every page returned `200`, had no horizontal overflow,
and opened with its current task or the one decision it supports before the
longer explanation and history.

Production: Composer `bbe9e2246a853b37904ae22a55350f3d2ad3cf43` / Worker
`4c2683dd-9916-4864-aa2d-09e3c35cd164`.

## Pages and first task

| Page | First task/state |
| --- | --- |
| Needs attention | The retained problem and its next action: connected app source changed → Open App resources |
| Creator stacks | Selected stack state and next action: published revision, saved revision, Open public page |
| Internal platform | Team access and current requests/policy before the request form |
| Workspace access | Choose a workspace and manage editor/viewer access; role and access revision visible |
| Analytics & outcomes | Current private scope, period and export before the measured results |
| Workspace maintenance | Keep an approved Guestbook copy; choose a book, check connection, prepare the file |
| Private enquiries | Next pending brief or the honest no-pending state; review is explicit |
| Workflows | The single most relevant recipe/run and its supported action (Save & turn on) |
| Orders | Selected order state, amount/provider/fulfilment and the next safe action |
| Connections | Selected connection and the supported owned-resource check |
| App resources | Recorded resources, owning stack, expected settings and the last app-confirmed operation |
| Agent proposals | Proposal-only boundary, then the scoped connection action |
| Plugin Trust Centre | Selected installed plugin, native/build-time comparison and owning-repository review |
| Stack status | “Needs review 1 item(s) need a decision” before the detailed policy table |
| Brand Studio | Current app/environment/account and appearance choices before the preview/publish detail |
| Incident Desk | Review/send back/approve the investigation before the proposal queue |
| Manage mini-apps | Review a contribution, feature it, open the result; source boundaries stay visible |

## Checks

- 17 admin pages × 2 viewports: all `200`; zero horizontal overflow at 1440 and
  390. The audit also read each page's lead text to confirm it names a task or
  current state, not a generic definition.
- The only console message was the expected CSP refusal of Cloudflare's injected
  Insights beacon (`script-src 'self' 'unsafe-inline'`); no application error,
  failed action or broken page state was observed.
- The live visitor-book review, approval, feature and revocation journey used the
  same admin surface; see
  [`linkarooie-contribution-20261107`](../linkarooie-contribution-20261107/README.md).
- Public discovery and role/task journeys are recorded in
  [`role-journeys-20261107`](../role-journeys-20261107/README.md) and
  [`discovery-jobs-20261107`](../discovery-jobs-20261107/README.md).
- Earlier scoped waves recorded both themes, keyboard focus and 390/1440
  inspection for Needs attention, Connections, Plugin Trust, Workflows, Creator
  stacks, Orders and Private enquiries.

## Residual scope

The 320px/200% zoom and physical screen-reader/device checks remain general
accessibility acceptance, not a claim in this audit. The admin IA itself is now
task-first across the live pages; deeper feature work stays with each owning
issue (#116, #198, #213, #289, #311, #353, #365 and so on).
